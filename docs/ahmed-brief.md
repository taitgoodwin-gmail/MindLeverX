# Ahmed — MindLeverX brief
**20 September 2026 · orientation, not an approved new scope**

**Purpose.** Help businesses understand how they appear in AI answers, led by what potential customers see in ChatGPT. Give clients understandable findings, supporting evidence, limitations and useful next actions. Search readiness and observed AI answers remain separate; visibility or revenue improvements are not guaranteed.

**MVP direction.** Proposed first-sale journey: website URL → essential intake and authorization → one-time payment → bounded evidence collection → report preparation and review → private delivery. Repeat monitoring and renewal follow. Buyer, price, precise package and one-off release policy remain decisions. Monthly reports require owner release approval; managed customer-site implementation is not agreed subscription scope.

**What exists.** The [public website](https://mindleverx.com/) is live. A newer **local-only** product has saved-results inspection, PDF generation, immutable report revisions, a review queue and portable evidence export. Qualified collection, accepted pilot scope, production identity, payment and private delivery are unfinished. Local approval does not send a report.

**What to trust.** [Start here](collaborator-start.md) identifies exact code versions and a tested setup. [Linear](https://linear.app/mindleverx-codex-build/project/mindleverx-next-release-bc7bec6a8dc4) owns work status. The [97-row requirements register](https://github.com/taitgoodwin-gmail/MindLeverX/blob/e976747564a5d039ac42129ab085246e77f8d1a9/docs/requirements-rubric-review/revised-requirements.md) is a review draft, not blanket approval; the older Google Sheet is not synchronized. The [Figma concept](https://www.figma.com/design/UgtCQvjyZpBQVOxhZAK4sk?node-id=2-129) is proposed, not the live site or an accepted specification. Final combined Figma visual verification remains incomplete.

**Recommended first contribution — confirm together.** Walk through the existing customer journey and local report experience, then propose one bounded UX improvement. Return an annotated flow or screens, the most important usability gaps, one implementation slice with dependencies and an effort estimate. Keep hypothetical states visibly labeled. Do not begin a wholesale redesign or rebuild completed report plumbing.

**Success for that first contribution.** We can identify the intended user, the change and why it helps, the affected requirement IDs and their authority, observable acceptance checks, and unresolved decisions. The owner chooses the slice; Ahmed supplies design/development judgment. Ahmed has not yet accepted an assignment or estimate.

**Design priorities.** Clear owner/client experience; low effort; reusable delivery; recurring value; automation; useful AI intelligence; evidence-informed behavioral design and competitive differentiation. These are product principles, not measured achievements. Start from the existing visual direction; use the Figma concept as discussion material.

**Before work.** GitHub, Linear and Figma access must be verified with Ahmed's accounts; invitations have not been sent. Use a separate feature branch and a focused PR. The default branch is deployment-connected. Do not merge, release, spend, contact customers or change an accepted product direction as part of this orientation.
